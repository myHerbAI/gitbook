# Product readiness

Use this checklist for every guide, template, course, membership or software product.

## Content

* The audience, problem and outcome are clear.
* The complete deliverable exists and has been reviewed.
* Sources, dates, authorship and licenses are documented.
* Claims are accurate and do not imply unverified partnerships or results.

## Commercial setup

* The exact price, taxes, currency and fees are known.
* The product page matches the delivered item.
* Terms, privacy, license, cancellation and refund rules are visible.
* A real end-to-end payment and payout test has passed.

## Delivery and support

* A buyer receives the correct file, access or account automatically.
* Mobile and desktop access have been tested.
* Support and recovery routes work.
* Updates, versioning and customer communication have an owner.

## Release states

| State | Meaning |
|---|---|
| Planned | Idea or outline only |
| Draft | Deliverable is being created |
| Prototype | Usable experiment; release requirements incomplete |
| Ready for test | Content and setup complete; end-to-end verification pending |
| Available | Checkout, delivery and support verified |
| Retired | No longer offered; preserved for history where appropriate |

{% hint style="info" %}
Publishing documentation is not the same as releasing a product. A product becomes available only after the full buyer journey passes.
{% endhint %}
