# How to use this library

## 1. Start with the status

Every important resource should state whether it is:

* **Available** — published and usable for the stated purpose;
* **Public reference** — free educational or reference material, not a paid product;
* **Draft** — still being edited or tested;
* **Prototype** — a working experiment that has not passed release checks;
* **Planned** — a proposed resource that does not yet exist as a deliverable;
* **Historical** — preserved evidence of earlier work, not a statement of current availability.

If a page does not yet carry a status, treat availability as **unverified**.

## 2. Follow the source

Where possible, pages link to the original article, repository, tool or source record. A polished page or repository is not proof that a product is production-ready, commercially available or authored by a particular person.

## 3. Use the right layer

* **GitBook:** public explanations, guides, documentation and product previews.
* **myHerb website:** brand pages, product pages, checkout, accounts and delivery.
* **GitHub:** source code, technical history and preserved repository evidence.

## 4. Report a problem

When a link, claim or product status looks wrong, use the contact route on the main myHerb website. Include the page URL and the specific text that needs review.
